# Отчёт: аудит, исправления и идеи развития

Аудит охватил все подсистемы: ядро/поток управления, радио (RC/CC1101/raw),
файловую систему/JSON, периферию/настройки, классические игры и движок Space
Impact, а также структуру сборки. Найдено и подтверждено (перепроверкой по коду)
**77 замечаний**: 6 высоких, 35 средних, 36 низких. Ниже — что исправлено, что
осознанно НЕ трогалось и почему, и что стоит добавить.

Все изменения проверены сборкой PlatformIO. Итог по памяти:

| | RAM | Flash |
|--|-----|-------|
| База (до) | 53 880 B | 742 237 B |
| После | 53 664 B | 738 717 B |

> ⚠️ Прошивка проверена только **компиляцией** — на реальном ESP32 её не запускали.
> Поведенческие исправления (радио-тайминги, BLE, игры) обязательно проверьте на
> железе. Откат: ветка `refactor-baseline-backup` указывает на исходное состояние.

## 1. Критические исправления (high)

| Проблема | Файл | Что сделано |
|----------|------|-------------|
| Зависание перебора 12-бит при `iy ≤ 0` (0·10 == 0 < 1000 → вечный цикл → watchdog) | `main.cpp` | `iy` ограничен `[1,4095]`, оба цикла-отступа защищены `draw > 0` |
| На «чистом» устройстве все сохранения были no-op (`.add<JsonObject>()` + `.as<JsonObject>()` над массивом → null) | `main.cpp` | инициализация через `.to<JsonObject>()`, после загрузки — фолбэк `isNull() → .to<>()` (данные не затираются) |
| `RecordSignal`: локальная `lastRecordDuration` затеняла глобальную → условие по времени мёртвое, короткие сигналы (<64 переходов) не записывались никогда | `hal/radio.cpp` | убрано затенение, глобальная сбрасывается в начале записи |
| Space Impact: `malloc` без проверки на NULL → гарантированный крах при фрагментации кучи на 20 fps | `games/si_engine.h` | проверки NULL во всех `malloc` (выстрелы, враги, объекты, пейзаж); при нехватке памяти элемент просто не создаётся |
| `gpioPins.h`: объекты `pin1/pin2/pin3` определены в заголовке без guard → ODR-мина при подключении из второго `.cpp` | `hal/gpioPins.*` | `#pragma once`, объекты объявлены `extern`, определены в `gpioPins.cpp` |

## 2. Структура и сборка (устранение хрупкости)

- **`#pragma once`** добавлен во все ~19 заголовков, где его не было.
- **Единый `config/pins.h`** — вся распиновка в одном месте; убраны дубли `#define`
  пинов, которые были и в `global_vars.h`, и в `global_vars.cpp`.
- **Убран запутанный дубль** `pinsCount(4)` / `pinsCounts(3)` — остался один
  `pinsCounts = GPIO_OUT_PIN_COUNT`; исключён потенциальный выход за границу
  `OutPinModeG[]`.
- **Реестр модулей** `core/menu.h` + `runMenu()` — меню стали таблицами `MenuItem[]`;
  добавление пункта = одна строка (см. `03_ADDING_MODULES.md`). Заодно исчезли
  «пустые» строки-заглушки в меню Games/Bluetooth/Settings, на которые заезжал курсор.
- **Каталоги** `config/core/hal/ui/apps/games` + `-I`-пути в `platformio.ini`.
- **`platformio.ini`** почищен (без дублей `platform`/`framework` в env); версии
  библиотек фиксируются копиями в `lib/` — из `lib_deps` убран явный пин
  ArduinoJson, который приводил к скачиванию несовместимой 7.4.x.
- **Кириллический ключ** `externalССModule` → ASCII `externalCCModule`.
- **Дубли макросов** `SCREEN_WIDTH/HEIGHT/boardSize` убраны из игровых заголовков.
- Удалён мёртвый код: `editPinParametr`, `digitalRead(RCPin);` без результата,
  неиспользуемые объявления `draw()/changeDirection()/update()` в `Game2048`,
  неиспользуемый буфер `recordedSignal[4096]` (**−16 КБ DRAM**).

## 3. Зависания и гонки

- **`detectSignal()`** больше не рекурсивен (перезапуск по OK был `detectSignal();`
  внутри себя → рост стека). Теперь внешний цикл перезапуска.
- **`run()` в обеих играх** (2048, Cat) — перезапуск после Game Over был рекурсией
  `run()→run()`; заменён на итеративный внешний цикл.
- **Экран RxBW** (`settings.cpp`) — убрана вторая FreeRTOS-задача на ядре 1. Она
  давала сразу три бага: гонку за общими `tiles/updDisplay/RxBW_Raw` (мьютекс
  защищал только читателя), утечку семафора (создавался на каждый вход, не
  удалялся) и `vTaskDelete` в момент удержания мьютекса/записи в I2C. Отрисовка
  раз в секунду не требует второго ядра — теперь всё в одном цикле.
- **Перебор 12-бит**: защищён и первый цикл-прогресс (падал при `start12bitBruteForce == 0`).

## 4. Производительность

- **`getVolltage()`**: было 64 блокирующих `analogRead` + `Serial.println` на КАЖДУЮ
  перерисовку главного экрана. Теперь кеш с пересчётом раз в секунду, 16 отсчётов,
  без Serial.
- **`detectSignal()`**: список частот сканировался дважды подряд идентично —
  дубликат удалён (вдвое меньше операций setMHZ/getRssi по SPI).
- **`saveJsonToFile()`**: прямой стрим в файл вместо сериализации в растущую
  `String` (меньше фрагментации кучи); убран отладочный дамп всего JSON в Serial.
- **`viewer()`**: `JsonArray` больше не резолвится из документа на каждый кадр —
  используется уже полученный `arr`; удалена мёртвая `static` переменная.
- **Space Impact**: между кадрами добавлен `delay(1)` (отдаёт CPU, кормит watchdog).

## 5. Функциональные баги

- **CC1101/raw**: `uint16_t tmmm = millis()` (усечение) → `unsigned long`;
  `RecordSignal` возвращает статус, и `rawLay` не сохраняет частичную запись при
  прерывании по back; в `sendSamples` локальная `delay` (затеняла `delay()`)
  переименована, удалена неиспользуемая `time`.
- **GPIO**: пины 2 и 3 теперь реально переключаются (раньше вызывался только
  `change()` без `start()/off()`); OK на подстроках учитывает выбранную строку;
  подписи показывают реальные GPIO (32/33/25); каждый пин на своём LEDC-канале
  (2/3/4) — устранён конфликт таймера с бипером (канал 1).
- **2048**: старт с 2 тайлов (а не 4); новые тайлы 90% «2»/10% «4» (было всегда «4»
  из-за `random(1)`); тайл добавляется только если ход изменил поле.
- **GameCat**: `resetGame()` сбрасывает флаг `out`; поле `uint8_t` вместо `uint16_t`.
- **Space Impact**: `SI_GetEnemy` проверяет данные ДО выделения (не кэширует мусор);
  размер врага берётся по всем кадрам анимации (был по нулевому); устранено чтение
  освобождённой памяти в цикле столкновений; исправлен выход за границу `Start[-1]`
  в таблице рекордов; буфер `ScoreText` расширен до 12 (защита от битого сейва).
- **Ввод**: диапазоны АЦП кнопок стыкуются без зазоров (нижняя граница `>=`).
- **Диалоги**: курсор удаления RC (`deleteRC`) всегда открывается на «No»
  (был `static` — мог открыться на «Yes»); подменю `menuRc` открывается на первом пункте.
- **`view.cpp`**: защита от деления на ноль в `map()` при сильном зуме.
- **Настройки**: курсор ограничен реальными 5 строками (был общий ITEMS=8).

## 6. Что осознанно НЕ менялось (и почему)

| Замечание | Причина |
|-----------|---------|
| Логика захвата `tryRecordSignalToBuffer` (подсчёт коротких <80 мкс переходов завышает `size`) | Микросекундный тайминг захвата RF; правка рискует сломать основную функцию, а проверить без железа нельзя. **Рекомендуемая правка** — увеличивать счётчик только при реальной записи отсчёта и ресинхронизировать `currentInput` на пропуске, сохранив ограничитель 4096. |
| Добавить `yield()` внутрь цикла захвата | **НЕЛЬЗЯ**: `yield()` посреди µs-точного захвата разрушит тайминг записи. Аудиторская рекомендация здесь неприменима. |
| Движок Space Impact как `static` в заголовках | Работает как единый TU (включается только из `games.cpp`). Полное разделение на `.cpp` — большой риск для рабочего порта без возможности прогонов. `#pragma once` уже стоит. |
| Методы классов игр определены в заголовках | То же: один TU, ODR-нарушения нет. |
| `PixelMap` 1 байт/пиксель (4032 Б) вместо битовой упаковки (~504 Б) | Экономия RAM в обмен на усложнение отрисовки; сейчас RAM не в дефиците (16%). |
| `renderToOled` перебирает все 4032 пикселя с div/mod | Оптимизация (dirty-box/x-y счётчики) не тестируема без железа; риск визуальных багов. |
| `btStart()` перед `BleKeyboard.begin()` | Жизненный цикл NimBLE тонкий; убирать без прогонов рискованно. |
| `readJsonFromFile` не возвращает ошибку | Смена контракта требует переработки вызывающих; отдельная задача. |
| Отсутствие цели в GameCat (счёт захардкожен) | Это геймдизайн, а не баг; вынесено в идеи ниже. Флаг `out` уже починен. |
| `selectMouse()` — заглушка | Функционал не реализован в исходнике; см. идеи. |
| `SI_ScData`/уровни без bounds-guard | Безопасно, пока число уровней == 6; добавить проверку при расширении. |

## 7. Отклонённые при перепроверке замечания (4)

- «Циклы меню без `yield` → watchdog»: `tk()` неблокирующий, реальной блокировки нет.
- «Строковые ключи JSON churn'ят кучу на каждый кадр»: для коротких `int`-ключей
  на этой платформе выделения кучи не происходит в горячем пути так, как описано.
- «`JsonDocument` не освобождает ёмкость на `remove()`»: не соответствует модели
  памяти ArduinoJson v7.
- «`SI_HandleScenery` освобождает голову вместо удаляемого узла»: сценарий не
  воспроизводится при фактическом порядке узлов.

## 8. Что стоит добавить (идеи развития)

### Функциональность
- **WiFi-подсистема — РЕАЛИЗОВАНО** (`apps/wifi_app.cpp`, пункт меню WIFI). Четыре
  пассивных режима (только приём): сканер точек доступа (SSID/BSSID/RSSI/канал/
  шифрование), монитор загруженности каналов 1–13, сниффер кадров в promiscuous-
  режиме (счётчики mgmt/beacon/data/ctrl по каналу) и список станций в эфире
  (MAC/RSSI устройств). Активные/наступательные режимы (deauth, beacon-флуд,
  evil-twin, инъекция) сознательно НЕ добавлены — это DoS/атаки на чужие сети.
  Побочный эффект: библиотека Wi-Fi подняла Flash до ~87% раздела приложения
  (см. `02_ARCHITECTURE.md` §8).
- **WiFi-ретранслятор (STA+SoftAP c NAT) — НЕВОЗМОЖЕН на текущем фреймворке.**
  В прекомпилированном arduino-esp32 2.0.17 (IDF 4.4) IP-форвардинг отключён
  (`CONFIG_LWIP_IP_FORWARD is not set`), а функции NAPT (`ip_napt_enable`)
  скомпилированы из `liblwip.a` — проверено `nm`, определённых символов нет,
  вызов не слинкуется. Чтобы сделать настоящий ретранслятор, нужна пересборка
  фреймворка со своим `sdkconfig` (`CONFIG_LWIP_IP_FORWARD=y`,
  `CONFIG_LWIP_IPV4_NAPT=y`) — это переход на сборку arduino-as-IDF-component
  (дольше и сложнее). Сам STA+SoftAP без маршрутизации возможен, но клиенты не
  получат доступ к вышестоящей сети — то есть это не ретранслятор.
- **ИК-приёмопередатчик** (частый модуль для таких устройств): запись/воспроизведение
  ИК-команд, база популярных протоколов.
- **Декодирование субгигагерцовых протоколов** (Princeton, CAME, NICE, Keeloq-анализ)
  с показом расшифровки в UI, а не только «data/bytes».
- **NFC/RFID** (125 кГц / 13.56 МГц) при добавлении соответствующего модуля.
- **Хранение на SD-карте** вместо/вместе со SPIFFS — под большие библиотеки raw-сигналов.

### Качество жизни
- Сохранять `FrequencyPointer` и `RxBW_Raw` в `config.json` (сейчас сбрасываются при
  перезагрузке).
- Индикатор заряда в процентах + порог низкого заряда с предупреждением.
- Прокручиваемые списки и иконки в меню; общий помощник для «список из N строк».
- Экран «About» с версией прошивки (`FTC_FIRMWARE_VERSION`).
- Цель/победа в GameCat (толкнуть ящик на целевую клетку) — тогда счёт и `delay`
  станут осмысленными.
- Реализовать или честно помечать «Not implemented» пункт BLE Mouse.

### Инженерия
- Нативная среда PlatformIO (`env:native`) для юнит-тестов чистой логики (2048,
  разбор сигналов) без железа.
- OTA-обновление прошивки по Wi-Fi.
- Прошивка образа SPIFFS с дефолтными `config.json` (папка `data/`), чтобы «чистое»
  устройство стартовало с валидными файлами.
- Разнести CC1101-функции (`setupRx/Tx/func_*`) из `main.cpp` в `hal/radio.cpp`,
  а экраны RC/Raw — в отдельный `apps/`-модуль (следующий шаг реструктуризации).

### Производительность
- Частичные обновления OLED вместо полной перерисовки кадра.
- Битовая упаковка `PixelMap` в Space Impact (−~3.5 КБ RAM).
- Оптимизация `renderToOled` (x/y-счётчики без div/mod, dirty-box).
